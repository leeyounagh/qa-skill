# qa-2pass

Claude Code 스킬. **실화면 QA 를 두 패스로 나눠서** 돌린다.

```
/qa-2pass 근태 1차
```

## 왜 두 패스인가

명세를 먼저 읽으면 **명세가 서술한 것만** 보게 된다. 「명세대로 동작하지만 쓰기 불편한 것」은
영원히 안 잡힌다. 반대로 명세를 아예 안 보면 기획의도를 결함으로 올려 티켓 보드를 오염시킨다.

그래서 순서를 고정한다.

| | 무엇을 보는가 | 무엇을 못 보는가 |
|---|---|---|
| **1차** | 화면만. 권한 등급이 다른 계정으로 로그인해 사용자 눈으로 훑는다 | 명세·코드·이슈 트래커 **접근 금지** |
| **2차** | 1차 목록을 명세·프론트·백엔드 코드와 대조해 오탐을 걸러낸다 | — |

두 패스는 **산출물 파일로만** 연결된다. 1차 도중 명세나 코드를 열지 않는 것이 1차의 유효성 전부다.
그래서 절차를 파일로 쪼갰다 — 1차 모드에서는 `PASS1-blind.md` 만 읽는다.
한 파일에 다 넣으면 2차의 대조 절차가 컨텍스트에 먼저 들어와 1차 판정이 오염된다.

## 1차가 보는 5가지

1. **UX 불편** — 클릭 수, 되돌아가기, 포커스, 로딩 중 무반응, 막다른 길
2. **권한과 무관한 UI 의 데이터 일관성** — 같은 화면을 계정 등급별로 열어 표로 교차 비교
3. **문구 통일성** — 용어 혼용, 존댓말·마침표, 버튼 라벨, 띄어쓰기, 로케일 잔재
4. **기능 완성도** — 빈 상태, 실패 안내, 검증 누락, 새로고침 유지, 페이징
5. **표시 깨짐** — 창 크기 하나로 보면 거의 안 잡힌다. **표시 매트릭스**(최소 지원 폭 + 사이드바 펼침 · 모바일 최소 폭 · 글자가 긴 언어 · 최악 데이터)를 돌며
   측정기 `layout-probe.js` 로 잰다 — 페이지 가로 넘침 · 말없이 잘림 · 단어 중간 줄바꿈 · 가려진 버튼 · 부모 밖 잘림 · 창 밖 밀림 · 글자 겹침 · 같은 칩 중복.
   측정기가 짚은 곳은 요소 스크린샷으로 눈 확인한다. 2차에서는 표시 깨짐을 「기획확인」 · 「UX 제안」으로 미루지 않는다 — 읽을 수 없거나 누를 수 없으면 결함이고, 기획에는 고칠 모양만 묻는다

②가 계정을 여러 개 쓰는 이유다. 권한과 무관해야 할 값이 계정마다 다르면 그 자체가 결함 후보다.

## 2차의 판정 3분류

| 판정 | 조건 | 필수 |
|---|---|---|
| **결함** | 명세 위반 확정, 또는 명세가 침묵하지만 **대조군이 존재** | 조항번호·기준브랜치 확인결과·재현율 |
| **오탐** | 기획의도 **근거가 있다** / 측정 실패였다 / 미배포였다 | 조항번호 또는 티켓번호 — **근거 없는 오탐 판정 금지** |
| **기획확인** | 명세 침묵 + 대조군 없음. 코드로 판별 불가 | 기획팀에 물을 질문 문구 |

**「기획확인」을 오탐으로 밀지 않는 것**이 이 스킬의 핵심 규칙이다. 근거를 못 찾은 것과
기획의도인 것은 다르다. 그리고 **축 ① UX 불편은 명세로 판정되지 않는다** — 명세와 일치해도
불편할 수 있으므로 조용히 버리지 않고 개선 제안으로 남긴다.

오탐은 **지우지 않고 근거와 함께 판정서에 남긴다.** 다음 QA 에서 같은 것을 다시 올리는 것을 막는다.

## 판정서 — 명세 대비 두 묶음 · 화면 예시

2차 결과는 「결함 N건」 한 덩어리로 내지 않는다. **A 명세상 명확한 결함**(조항 문언 위반 · 층 대조 · 재현 완료)과
**B 명확하지 않은 것**(B1 대조군 근거 · B2 해석 필요 · B3 명세 침묵 · B4 UX 제안 · B5 명세 정정 후보)으로 나눈다.

화면을 봐야 이해되는 항목(모양 · 배치 · 화면 간 불일치 · 디자인 선택 · 스크린샷 불가)에만 **지금 / 고친 뒤 목업**을 붙이고,
판정서를 페이지별 HTML 로 낸다(`MOCKUP.md` · `verdict-template.html`). 재현 목업은 실측 폭으로 그리고 다시 재서 정말 깨지는지 확인한다.

## 3차 — API 계약 대조 (선택)

화면 QA 는 프론트가 막아 주는 요청만 본다. 3차는 세션 토큰으로 백엔드를 직접 불러 명세 부록(API · DTO · 검증 규칙)을
조항별로 대조한다 — enum 밖 값, 음수 페이지, 남의 id, 상한 없는 limit. **토큰 신원을 디코드해 확인하지 않고는 돌리지 않는다.**

## 재시험 — 고쳤다는 티켓을 다시 잰다

1 · 2차가 새 결함을 찾는다면, 재시험은 **고쳤다는 티켓을 티켓 원문 기준으로** Playwright 로 다시 재서
통과 · 실패를 정하는 사람에게 **근거**를 낸다. 티켓 상태는 옮기지 않는다.

- **자리 셋** — [A] 사전(PR 단계, 로컬 프론트 → 테스트 백엔드) · [B] 확인 보조(테스트 서버) · [C] 재작업 재시험(지난 실패 조건 + 회귀)
- **계약** — 티켓의 기대 결과 · 재현 절차 · 확인 범위 · 확인 요청 댓글을 기준표로 옮기고(`retest-contract.md`), 구현자 설명은 기준에 넣지 않는다
- **회귀 확장** — 실제 확인 실패는 「최악 데이터에서만 깨짐」 · 「다른 경로는 그대로」가 많다. PR 이 바꾼 파일로 진입점 전부 · 공용 부품 다른 사용처 · 최악 데이터 기준을 더한다(상한 8)
- **실행** — 새 컨텍스트의 서브에이전트에 기준표만 넘긴다. 저장 확인은 `scripts/save-guard.js` 로 실제로 쓰지 않고 요청 본문만 본다
- **판정** — PASS / FAIL / BLOCKED / INCONCLUSIVE. 열어 본 스크린샷만 증거, FAIL 은 2회 재현 · 반영 · 계정 · 데이터 확인 뒤
- **트래커 무관** — 절차는 트래커를 여섯 동작(목록 · 본문 · 댓글 · 상태 이력 · 연결 PR · 쓰기/이미지)으로만 부른다.
  어떤 트래커든(이슈 트래커 · 저장소 이슈 · 문서 DB · 시트 · 없음) 설정에 동작별 도구를 적고, 못 하는 동작은 붙여 넣기 · 글로 출력으로 대체한다

```
/qa-2pass 재시험 ABC-12 ABC-40          # 티켓 지정
/qa-2pass hr 재시험 확인 대기 전부       # 확인 대기 상태 목록에서 고르기
/qa-2pass 재시험 사전 #123              # PR 단계 사전 재시험
```

재시험을 처음 부르면 **재시험 온보딩**(`SETUP.md` C1~C16 — 트래커와 동작별 도구 · 상태 대응표 · 판정하는 사람 · 결과 전달 형식 ·
티켓 절 대응 · PR 연결 · 배포 확인법 …)을 시작 전에 한 번에 묻고, 답한 값을 실제로 한 번씩 해 본 뒤 시작한다.

## 1차를 건너뛰기

모드는 `1차` · `2차` · `3차` · `명세대조` · `재시험` 다섯이다. 1 · 2차 쪽 예:

```
/qa-2pass <기능> 2차 <1차목록 파일경로>   # 1차를 이미 했거나 남이 준 목록이 있을 때
/qa-2pass <기능> 명세대조                 # 블라인드 대신 명세 조항을 순서대로 훑는다
/qa-2pass <기능>                          # 모드 생략 = 1차부터
/qa-2pass                                 # 전부 생략 = 물어본다
```

2차 단독일 때 입력원이 없으면 **진행하지 않고 묻는다**(항목을 지어내면 안 되므로).
입력이 남이 준 목록이면 실측 근거가 없다고 경고하고 재현할지 확인한다.

## 오탐 함정 체크리스트

`FALSE-POSITIVES.md` 에 A~J 계열을 모아뒀다. 전부 실제 QA 에서 오탐을 만든 유형이다(아래는 일부 — I 는 표시 측정기 오탐, J 는 재시험의 「안 고쳐졌다」 오판).

- **측정 실패** — 토스트는 몇 초 만에 사라진다. 클릭 *전에* MutationObserver 를 심는다.
  안 닫은 얼럿은 이후 클릭을 전부 삼키는데, **이미 떠 있는 얼럿은 옵저버에 안 잡힌다**
- **미배포** — 테스트 서버에서 재현되는데 기준 브랜치에 수정이 있으면 결함이 아니라 배포 시차다
- **권한** — 메뉴가 보이면 권한이 있는 것. 「관리자인데 권한 없음」은 대개 계정 레코드 중복
- **로케일** — 계정 언어가 다른 계정은 화면이 그 언어로 나온다. 지원 대상 밖 언어의 결손은 오탐
- **서버 문구를 프론트 구현으로 오인** — 프로덕션 코드에 없고 테스트 픽스처에만 있으면 서버발
- **명세가 틀린 경우** — 명세 위반을 근거로 세우기 전에 **구현 층을 전부 대조**한다(조회 쿼리 + 존재하는 각 클라이언트. 층 개수는 도메인마다 다르다). 층이 다 일관되면 결함이 아니라 **명세 정정**이다. 함수 이름이 아니라 쿼리 본문을 읽을 것 — `FindApproved…` 가 실제로는 「반려·취소만 제외」일 수 있고, 그 이름을 믿고 적힌 주석까지 함께 틀려 있다

코드 근거는 **항상 배포 기준 브랜치**에서 읽는다(`git show <remote>/<브랜치>:<경로>`).
워킹트리는 현재 체크아웃된 브랜치를 보여줄 뿐이고, 구시점 분기면 「가드가 없다」고 오판한다.

## 설치

```bash
git clone https://github.com/leeyounagh/qa-skill
cp -r qa-skill/qa-2pass ~/.claude/skills/
```

프로젝트에만 쓰려면 `~/.claude/skills/` 대신 `<프로젝트>/.claude/skills/` 로 복사한다.

## 설정 — 한 번만 묻는다

환경별 값(테스트 서버 URL·계정·명세 위치·레포 경로)은 **스킬에 없다.** 설정 파일에서 읽는다.
설정은 **공통 1개 + 도메인별 N개**로 나뉜다.

```
$HOME/.claude/projects/<프로젝트>/memory/reference_qa_environment.md      # 공통 (권장)
$HOME/.claude/projects/<프로젝트>/memory/reference_qa_env_<도메인>.md    # 도메인별
$HOME/.claude/qa-2pass-config.md                                          # 공통 대안
```

**왜 나누는가.** 같은 서버·같은 레포라도 도메인(앱)마다 권한 체계·계정·명세·이슈 팀이 다르다.
한 파일에 섞으면 A 도메인 계정 등급으로 B 도메인 권한을 판정하게 된다. 그래서 QA 는
**공통 파일 + 대상 도메인 파일 하나만** 읽는다.

| 파일 | 받는 것 |
|---|---|
| 공통 | 테스트 서버 호스트 / 레포 경로 / 대조 기준 브랜치 / 도메인 목록(키·앱 디렉터리·basePath) |
| 도메인 | 진입 URL / 계정(id·pw·**권한등급**·계정언어·로그인 특이사항) / 기능↔화면경로↔명세문서 매핑 / 백엔드 서비스 경로 / 이슈 트래커 팀 / 도메인 함정 |

첫 실행 때 스킬이 물어서 파일을 만든다. 새 도메인을 처음 돌리면 **도메인 온보딩 체크리스트**
(`qa-2pass/SETUP.md` B1~B8, 필수 B1~B5)부터 진행하고, 필수 항목이 비면 QA 를 시작하지 않는다.
그 다음부터는 **다시 묻지 않는다.** `(미등록)` 인 필드만 묻는다.

```
/qa-2pass hr 근태 1차     # 도메인 명시
/qa-2pass 근태 1차        # 도메인 생략 — 기능명이 속한 도메인 파일에서 추론
```

**권한등급이 핵심이다.** 등급을 모르면 축 ②(계정 교차 비교)를 판정할 수 없다.
같은 id 라도 도메인마다 권한이 다를 수 있으니 등급은 **도메인별로 실측**해 적는다.

> ⚠ 비밀번호를 설정 파일에 적으면 평문으로 남는다. 로컬 전용 경로이지만, 파일을 공유할 일이
> 있으면 id·등급만 두고 pw 는 분리하는 편이 안전하다. **설정 파일은 이 레포에 올리지 않는다.**

기능 선택지는 매핑표에서 나온다. 표에 없는 기능을 지정하면 명세 위치를 묻고 **행을 추가**한다 —
「한 번만 묻는다」가 계정뿐 아니라 명세에도 적용된다.

## 반드시 묻는 지점

`AskUserQuestion` 은 자동 승인 모드에서도 사용자에게 올라간다. 위험은 도구가 막히는 게 아니라
**묻지 않고 스스로 판단해버리는 것**이라, 지점에 이름을 붙여 고정했다.

기능·모드 미지정 / 2차 입력원 없음 / **1차→2차 게이트** / 판정이 「기획확인」 /
**테스트 서버에 데이터 남기는 조작 직전** / **이슈 등록 직전** / 매핑표에 없는 기능 / 3차를 돌릴지 /
**재시험 기준표 게이트** / **재시험 결과를 트래커에 쓰기 직전** / 재시험 온보딩.
