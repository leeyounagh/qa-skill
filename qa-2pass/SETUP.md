# 최초 설정 — 한 번만 묻는다

환경별 값은 스킬에 넣지 않는다. 아래 위치의 설정 파일에 둔다.

```
$HOME/.claude/projects/<프로젝트>/memory/reference_qa_environment.md   ← 프로젝트별 (권장)
$HOME/.claude/qa-2pass-config.md                                       ← 사용자 공통 대안
```

프로젝트 메모리에 두면 세션 간 유지되고 색인에도 잡힌다. `SKILL.md` 0단계가 두 경로를 글롭으로 찾는다.

**파일이 이미 있으면 전체를 다시 묻지 않는다.** `(미등록)` 인 필드만 묻고 그 줄만 고친다.

## 묻는 것

`AskUserQuestion` 으로 받는다. 이미 아는 값은 보여주고 확인만 받는다.

| # | 항목 | 왜 필요한가 |
|---|---|---|
| 1 | 테스트 서버 URL | 1차 로그인 대상. `localhost` 가 아니다 |
| 2 | 계정 목록 — id / pw / **권한등급** / 계정언어 / 로그인 특이사항 | 등급을 모르면 축 ②(계정 교차 비교) 판정이 불가능하다 |
| 3 | 기능 ↔ 화면경로 ↔ 명세문서 매핑 | 기능 선택지가 여기서 나오고, 2차가 어느 명세를 읽을지 스스로 안다 |
| 4 | 코드 레포 경로 (프론트 · 백엔드) | 2차 코드 대조 대상 |
| 5 | 대조 기준 브랜치 | 배포분에 해당하는 브랜치 (예: `origin/test`, `origin/main`) |
| 6 | 이슈 트래커 팀·프로젝트 키 | 중복 검색과 등록 대상 |

**권한등급은 최소 2개, 가능하면 3개 이상** 받는다 — 최고 권한 / 일부 권한 / 일반.
외부 연동(SSO·메일)이 안 걸린 계정이 있으면 그것도 표시한다. 검사 축이 하나 늘어난다.

⚠ 비밀번호를 이 파일에 적으면 평문으로 남는다. 로컬 전용 경로이지만,
파일을 남과 공유할 일이 있으면 id·등급만 두고 pw 는 분리하는 편이 안전하다.

## 파일 포맷

```markdown
---
name: reference-qa-environment
description: qa-2pass 스킬 설정 — 테스트 서버·계정(권한등급)·기능↔명세 매핑·레포 경로
metadata:
  type: reference
---

## 테스트 서버
- URL: <값>
- 빌드 시점 확인법: <있으면>

## 계정
| id | pw | 권한등급 | 계정언어 | 특이사항 |
|---|---|---|---|---|

## 기능 ↔ 명세 매핑
| 기능 | 화면 경로 | 명세 문서 | 상태 |
|---|---|---|---|

## 레포
- 프론트: <경로>   백엔드: <경로>   대조 기준 브랜치: <remote>/<브랜치>

## 이슈 트래커
- 팀·프로젝트: <키>
```

프로젝트 메모리에 만들었으면 그 프로젝트의 메모리 색인에 한 줄 포인터를 넣는다.

## 매핑표를 키우는 것도 설정이다

매핑표에 없는 기능으로 QA 를 시작하면 — 명세 위치를 묻고 **행을 추가한 뒤** 진행한다.
「한 번만 묻는다」는 계정뿐 아니라 명세에도 적용된다.

화면 경로는 **추측하지 말고 레포의 라우트 구조에서 실측해** 채운다.

명세가 아직 없는 기능이면 `상태` 를 `(명세 없음)` 으로 적는다. 그 기능의 2차는
**대조군과 이슈 코퍼스만으로** 판정하고, 명세가 필요한 항목은 전부 「기획확인」으로 간다.

## 정본과 보관본

명세는 정본·보관본이 따로 있을 수 있다. 매핑표에는 **정본만** 적고, 보관본 id 는 적지 않는다 —
적어두면 언젠가 그걸 읽고 이미 반영된 변경을 결함으로 오판한다.
