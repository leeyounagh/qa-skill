# 최초 설정 — 한 번만 묻는다

환경별 값은 스킬에 넣지 않는다. 설정은 **공통 1개 + 도메인별 N개**로 나눠 둔다.

```
$HOME/.claude/projects/<프로젝트>/memory/reference_qa_environment.md      ← 공통 (권장 위치)
$HOME/.claude/projects/<프로젝트>/memory/reference_qa_env_<도메인>.md    ← 도메인별
$HOME/.claude/qa-2pass-config.md                                          ← 공통 대안 (사용자 공통)
```

**왜 나누는가.** 같은 테스트 서버·같은 레포라도 도메인(앱)마다 **권한 체계·계정·명세 DB·이슈 팀**이 다르다.
한 파일에 섞어 두면 A 도메인 계정 등급으로 B 도메인 권한을 판정하는 사고가 난다.
공통 파일은 도메인 목록(색인)을 들고, QA 는 **한 번에 한 도메인 파일만** 읽는다.

**파일이 이미 있으면 전체를 다시 묻지 않는다.** `(미등록)` 인 필드만 묻고 그 줄만 고친다.

## A. 공통 온보딩 — 프로젝트당 1회

`AskUserQuestion` 으로 받는다. 이미 아는 값은 보여주고 확인만 받는다.

| # | 항목 | 왜 필요한가 |
|---|---|---|
| A1 | 테스트 서버 **호스트** | 도메인 진입 URL = 호스트 + basePath. `localhost` 가 아니다 |
| A2 | 코드 레포 경로 (프론트 · 백엔드) | 2차 코드 대조 대상 |
| A3 | 대조 기준 브랜치 | 배포분에 해당하는 브랜치 (예: `origin/test`) |
| A4 | 도메인 목록 — 키 / 앱 디렉터리 / basePath | 도메인 선택지. basePath 는 **각 앱 설정 파일에서 실측**한다(추측 금지) |

## B. 도메인 온보딩 — 도메인당 1회 (체크리스트)

도메인 파일이 없는 도메인으로 QA 를 시작하면 이것부터 한다. **B1~B5 가 비면 QA 를 시작하지 않는다.**

| # | 항목 | 필수 | 왜 필요한가 |
|---|---|---|---|
| B1 | 도메인 키 · 앱 디렉터리 · basePath · 진입 URL (모바일 경로 있으면 함께) | ● | 1차 로그인 대상. 호스트가 공통과 다르면 여기 적는다 |
| B2 | 계정 — id / pw / **권한등급** / 계정언어 / 로그인 특이사항 | ● | 등급을 모르면 축 ②(계정 교차 비교) 판정 불가. **이 도메인에서의** 등급이다 |
| B3 | 기능 ↔ 화면경로 ↔ 명세문서 ↔ 상태 매핑 | ● | 기능 선택지 + 2차가 읽을 명세. 경로는 라우트 구조 실측 |
| B4 | 백엔드 정본 서비스 경로 | ● | 2차 BE 대조 범위. 모노레포면 서비스 디렉터리 |
| B5 | 이슈 트래커 팀·프로젝트 키 (+ 담당자 규칙) | ● | 중복 검색과 등록 대상 |
| B6 | 빌드 시점 확인법 (배포 슬롯 조회 등) | ○ | 「안 고쳐졌다」가 미배포인지 판정 |
| B7 | 명세 DB 위치 (기능명세서가 모인 곳) | ○ | 매핑표에 없는 기능이 나왔을 때 검색 출발점 |
| B8 | 도메인 함정 — 관리자 명단 API, 화면으로 못 만드는 데이터 등 | ○ | 오탐 사전 차단. QA 를 돌리며 쌓는다 |
| B9 | **표시 매트릭스 · 표시 기준선** — 지원 폭(데스크톱 최소 · 모바일 최소) · 사이드바처럼 본문 폭을 바꾸는 요소 · 글자가 긴 언어 · 이미 정해진 표시 결정(번호 + 인용) | ○ | 1차 축 ⑤ 의 창 크기 · 2차 표시 깨짐 판정 근거. 없으면 1차는 기본값으로 돌고, 2차는 대조군 · 측정 수치로만 판정한다 |

**B2 규칙:** 권한등급은 **최소 2개, 가능하면 3개 이상** — 최고 권한 / 일부 권한 / 일반.
외부 연동(SSO·메일)이 안 걸린 계정이 있으면 표시한다. 검사 축이 하나 늘어난다.
다른 도메인 계정을 그대로 복사하지 않는다 — 같은 id 여도 도메인마다 권한이 다를 수 있으니 **이 도메인에서 실측**한 등급을 적는다.

⚠ 비밀번호를 파일에 적으면 평문으로 남는다. 로컬 전용 경로이지만,
파일을 남과 공유할 일이 있으면 id·등급만 두고 pw 는 분리하는 편이 안전하다.

온보딩이 끝나면 공통 파일 도메인 목록의 그 행 `설정 파일`·`상태` 를 채운다.

## C. 재시험 온보딩 — 도메인당 1회, 재시험을 처음 부를 때만

1 · 2차만 쓰는 도메인에는 묻지 않는다. 재시험(`RETEST.md`)을 처음 부르면 도메인 파일 「재시험」 절을 보고,
**● 칸이 비어 있으면 재시험을 시작하기 전에 한 번에 묻는다.** 시험 도중에 하나씩 묻지 않는다.
`AskUserQuestion` 은 한 번에 4문항이라 2~3회로 나눈다. 이미 아는 값(다른 절 · 레포에서 실측한 값)은 보여 주고 확인만 받는다.
B1~B5 도 비어 있으면 **B → C 순서**로 묻는다.

### 묻고 끝내지 않는다 — 실측 확인

답만 받아 적으면 틀린 값이 첫 재시험에서야 드러난다. 온보딩 끝에 아래를 **실제로 한 번씩** 해 보고, 된 것만 칸 끝에 `(확인 <날짜>)` 를 붙인다.
**쓰기는 하지 않는다** — ⑥ 은 도구 · 권한만 확인하고, 실제 게시는 첫 재시험 때 사용자 승인과 함께 처음 한다.

| 확인 | 방법 | 실패하면 |
|---|---|---|
| C1 ①~⑤ | C2 「확인 대기」 티켓 1건으로 목록 · 본문 · 댓글 · 상태 이력 · 연결 PR 을 한 번씩 | 그 동작만 「못 함 → 대체」. 다섯 다 안 되면 붙여 넣기 방식 |
| C5 | 그 티켓(+ 사용자가 고른 1~2건)으로 기준표 초안을 보여 주고 「이렇게 읽는 게 맞나요?」 | 절 이름 보정 |
| C6 · C7 | 그 티켓의 연결 PR 을 찾고 배포 확인을 1회 | 방법 보정 또는 「사람에게 묻기」 |
| C8 | 로컬로 띄워 로그인 화면 200 확인 → 포트 · PID 로 종료 | [A] 끔 |
| 계정 | B2 계정마다 로그인 1회 + 토큰 신원 확인 | 그 계정 제외 · 보고 |

온보딩이 끝나면 공통 파일 도메인 목록의 그 행 `재시험` 칸에 `설정됨(<날짜>)` 을 적는다.

## 매핑표를 키우는 것도 설정이다

매핑표에 없는 기능으로 QA 를 시작하면 — 명세 위치를 묻고 **그 도메인 파일에 행을 추가한 뒤** 진행한다.
「한 번만 묻는다」는 계정뿐 아니라 명세에도 적용된다.

화면 경로는 **추측하지 말고 레포의 라우트 구조에서 실측해** 채운다.
다른 앱의 화면을 대조군으로 쓰는 경우(예: 모바일 화면의 데스크톱 대조군이 다른 앱에 있음) 상태 칸에 **앱 이름까지** 적는다.

명세가 아직 없는 기능이면 `상태` 를 `(명세 없음)` 으로 적는다. 그 기능의 2차는
**대조군과 이슈 코퍼스만으로** 판정하고, 명세가 필요한 항목은 전부 「기획확인」으로 간다.

## 정본과 보관본

명세는 정본·보관본이 따로 있을 수 있다. 매핑표에는 **정본만** 적고, 보관본 id 는 적지 않는다 —
적어두면 언젠가 그걸 읽고 이미 반영된 변경을 결함으로 오판한다.

## 구버전 단일 파일 이관

공통 파일에 계정·매핑표·이슈 팀까지 들어 있으면 구버전이다. 이렇게 나눈다.

1. 계정·매핑표·이슈 팀·도메인 특이 메모 → `reference_qa_env_<도메인>.md` 로 **그대로** 옮긴다(값 수정 금지)
2. 공통 파일엔 호스트·레포·기준 브랜치·도메인 목록만 남긴다
3. 메모리 색인에 도메인 파일 포인터를 추가한다
