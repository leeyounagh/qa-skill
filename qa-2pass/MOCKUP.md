# 판정서 화면 예시(목업) — 필요한 항목에만

판정서를 받는 사람(PM · 개발)은 글로 된 「1280 에서 라벨이 잘린다」를 읽고도 **어디가 어떻게** 깨졌는지 다시 화면을 열어 봐야 했다.
그래서 화면을 봐야 이해되는 항목에만 **지금 / 고친 뒤** 두 칸 목업을 붙이고, 판정서를 **페이지별**로 묶는다.
전부 그리지 않는다 — 목업이 필요 없는 항목에 그림을 붙이면 판정서가 길어지고 정작 봐야 할 그림이 묻힌다.

**목업은 2차 산출물이다.** 「고친 뒤」는 명세 · 표시 기준선 · 대조군을 알아야 그릴 수 있어서 1차에서는 만들지 않는다(1차는 스크린샷만).

## 1. 만들지 판단 — 아래 중 하나일 때만

| 만든다 | 예 |
|---|---|
| ① **모양이 문제**인 것 — 축 ⑤ 표시 깨짐 전부 | 라벨 말줄임 · 세로 꺾임 · 겹침 · 하단 바가 버튼을 가림 |
| ② **위치 · 배치 · 순서**가 문제인 것 | 버튼이 엉뚱한 줄에 · 탭 순서 · 빈 상태 문구가 두 번 |
| ③ **화면 사이 불일치** — 두 화면을 나란히 놓아야 보이는 것 | 같은 「승인 대기」 칩이 화면마다 다른 색 · 같은 동작 버튼 라벨이 다름 |
| ④ **고칠 모양을 골라야** 하는 것(디자인 선택 질문) | 조직 트리 안 A 말줄임 / B 두 줄 / C 배지 축약 — 안마다 한 칸 |
| ⑤ 스크린샷을 **그대로 못 쓰는** 것 | 실기기 제보(사진뿐) · 개인정보가 찍힌 화면 · 순간만 보이는 상태 |

| 만들지 않는다 | 대신 |
|---|---|
| 문구만 틀린 것 | 판정서에 지금 문구 / 바꿀 문구를 인용 |
| 데이터 · 건수 · 권한 · API 계약 불일치 | 계정 교차 표 · 요청/응답 표 |
| 안내 · 토스트가 없는 것 | 옵저버 기록 |
| 오탐 · 측정 실패 · 미배포 | 근거 한 줄 |

**양 제한** — 페이지당 목업 2~3개. 한 페이지에 깨짐이 여럿이면 **한 목업에 번호 표식(①②③)** 으로 묶는다.
판정서 전체에서 10개가 넘으면 항목을 다시 본다 — 대개 ①이 아닌 것에 그렸다.

## 2. 무엇을 그리나

- **문제 영역만** 그린다. 전체 화면이 아니라 그 칸 · 그 줄 · 그 창, 그리고 어디인지 알 만큼의 주변(페이지 제목이나 탭 한 줄)까지만.
- **두 칸** — 왼쪽 「지금」, 오른쪽 「고친 뒤」. ④ 디자인 선택은 「지금 · 안 A · 안 B …」.
  ③ 화면 사이 불일치는 「화면 X · 화면 Y」를 나란히 놓고, 고친 뒤 칸에 둘이 같아진 모양을 둔다.
- **「지금」 칸은 실측이 근거다.** 1차 요소 스크린샷(`screenshot <ref>`)을 우선 쓴다. 스크린샷이 없거나 ⑤ 사정이면
  HTML 로 재현하되 **측정기 수치(칸 폭 · 글자 수)를 그대로** 써서 실제와 같은 모양으로 깨지게 만든다 —
  넉넉한 폭으로 그려 놓고 「이렇게 깨진다」고 적으면 거짓 그림이다. 재현이면 캡션에 「코드로 재현한 도식」이라 적는다.
- **「고친 뒤」 칸은 제안이다.** 머리에 근거를 단다 — 표시 기준선 번호 · 명세 조항 · 대조군 화면.
  근거 없이 모양을 정한 칸은 「제안 — 확정 아님」 표시를 붙인다. ④ 는 안마다 장단을 한 줄씩.
- **표식** — 봐야 할 곳에 점선 상자 + 번호. 그림 아래 캡션 한 문장: 「점선 상자 ① 의 라벨을 본다 — 왼쪽은 「주민등…」, 오른쪽은 끝까지 보인다」.
- **재현 조건 캡션** — 폭 · 사이드바 · 언어 · 데이터(「1280 · 사이드바 펼침 · ja · 조직 4단계」).
- **개인정보는 가명** — 실명 · 연락처 · 주민번호 · 계좌는 「홍길동」 · 「010-0000-0000」 같은 값으로 바꾼다. 스크린샷이면 가린다.
- **모양은 비슷하게, 꾸미지 않는다** — 앱의 글꼴 · 칩 색 · 칸 높이를 대략 맞추고 그 이상 다듬지 않는다. 목업이 실제 화면보다
  예쁘면 「고친 뒤」가 실제 수정보다 커 보인다.

## 3. 만드는 법

판정서에 목업이 하나라도 있으면 판정서를 **HTML** 로 낸다(`<scratchpad>/pass2-verdict-<날짜>.html`). 뼈대는
`verdict-template.html` 을 복사해 쓴다 — 요약 · 기획확인 · **페이지별 절** · 오탐 순서와 목업 칸(`figure.mock`)이 들어 있다.

1. 항목마다 1절 표로 목업 필요 여부를 정하고, 판정 표 「화면 예시」 칸에 `M<번호>` 또는 「불필요(문구)」처럼 이유를 적는다.
2. 「지금」 스크린샷은 판정서 옆 `img/` 에 두고 상대 경로로 넣는다.
3. 브라우저로 열어 **목업 칸이 의도한 대로 깨지고 / 고쳐져 보이는지** 확인한다. 눈만 믿지 말고 재현 칸에 측정기(`layout-probe.js`)나
   `scrollWidth/clientWidth` 를 돌려 **실측과 같은 종류 · 비슷한 수치로 깨지는지** 본다. 캡션 수치는 이 재측정 값으로 적는다 —
   템플릿 예시를 만들 때도 85px 로 그렸더니 라벨이 다 들어가 안 깨졌다(실측 폭 64px 에서야 「주민등록…」).
4. 이슈 등록 때 쓸 PNG 를 목업마다 뽑는다.

```bash
playwright-cli goto "http://localhost:<port>/pass2-verdict-<날짜>.html"   # file:// 은 막혀 있다 — python -m http.server 로 띄운다
playwright-cli snapshot                                                    # figure#M3 의 ref 확인
playwright-cli screenshot <ref>                                            # → mock-M3.png
```

이슈를 올릴 때(`PASS2-verify.md` 이슈 등록) 그 항목의 PNG 를 본문 「현상」 바로 아래에 붙이고 캡션 문장을 그대로 쓴다.
목업 없이 올라간 깨짐 티켓은 개발자가 재현부터 다시 한다.
