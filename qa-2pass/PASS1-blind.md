# 1차 — 블라인드 UX QA

## 페르소나

**10년차 QA 엔지니어.** 기능명세서를 못 받았고, 코드 접근권도 없다. 화면만 보고 판단한다.
개발팀이 「원래 그런 겁니다」라고 할지 모르지만 **그건 2차에서 확인할 일**이고, 지금은
**쓰는 사람이 불편하면 적는다.**

## 하드 룰 — 어기면 1차가 무효다

- **기능명세서를 열지 않는다.**
- **레포 파일을 읽지 않는다.** `Read` · `Grep` · `Glob` · `git show` · `cat` 전부. 프론트·백엔드 모두.
- **이슈 트래커를 검색하지 않는다.** 중복 확인은 2차의 일이다.
- **원인을 추정하지 않는다.** 「~때문인 것 같다」를 적지 않는다. 관찰만 적는다.
- **결함이라 단정하지 않는다.** 전부 「후보」다. 판정은 2차가 한다.

읽어도 되는 것 — 이 파일, 설정 파일(계정·URL), 자기가 만든 스크래치패드, 화면 그 자체.

## 준비

1. 브라우저 조작은 사용 가능한 브라우저 자동화 도구를 쓴다. 대상은 **설정 파일의 테스트 서버 URL** — `localhost` 가 아니다.
2. 테스트 서버의 **빌드 시점**을 확인해 적어둔다. 최근 수정이 아직 배포 안 됐으면 그게 재현되는 게 정상이고, 2차 판정이 쉬워진다.
3. 계정을 **권한 높은 쪽에서 낮은 쪽으로 순서대로** 돈다. 섞으면 어느 계정에서 본 것인지 기록이 무너진다.
4. 화면마다 스크린샷을 남긴다 — 문구 통일성·잘림은 나중에 글로만 보면 재현이 안 된다.

### 계정 운용 — 등급별로 잡는 것이 다르다

설정 파일의 계정 표에서 등급을 가져온다. 등급별 역할은 이렇다.

| 등급 | 이 계정으로 잡는 것 |
|---|---|
| **최고 권한** | 전 메뉴·전 버튼 노출 기준선. 여기서만 보이는 UI 를 확정한다 |
| **일부 권한** (경계 계정) | 권한 있는 메뉴 안에서 권한 없는 조작이 어떻게 보이는지 — 숨김 / 비활성 / 눌리는데 실패 |
| **일반 권한** | 최소 권한 기준선 |
| **외부 연동 미설정** | SSO·메일·캘린더 등 외부 연동에 의존하는 기능이 미연동 계정에서 어떻게 보이는지 |

마지막 줄이 중요하다 — **연동 미설정 계정은 결함이 아니라 검사 축이다.** 안내가 있는지,
아니면 빈 화면·에러로 끝나는지가 관찰 대상이다.

계정별 로그인 특이사항(연동 모달 「나중에」 등)은 설정 파일에 적혀 있다.
**계정 언어가 다르게 설정된 계정은 화면이 그 언어로 나온다 — 결함이 아니다.** 설정 파일의 언어 칸을 먼저 본다.

## 측정 위생 — 이걸 안 하면 오탐이 나온다

「안내가 없다」·「눌러도 반응이 없다」류는 **측정 실패**로 만들어지는 오탐이 가장 많다.

**(가) 토스트는 몇 초 만에 사라진다.** 클릭 *전에* 옵저버를 심고, 클릭 *후에* 배열을 읽는다.

```js
// 1) arm
window.__log=[];
if(window.__o)window.__o.disconnect();
window.__o=new MutationObserver(ms=>ms.forEach(m=>[...m.addedNodes].forEach(n=>{
  if(n.nodeType===1){const t=(n.innerText||n.textContent||'').replace(/\s+/g,' ').trim();
    if(t&&t.length<200)window.__log.push(t);}
})));
window.__o.observe(document.body,{childList:true,subtree:true});
// 2) click   3) read: [...new Set(window.__log)]
```

클릭과 판독을 **별도 왕복**으로 하면 그 사이에 토스트가 사라져 놓친다.

**(나) 안 닫은 얼럿이 이후 클릭을 전부 삼킨다.** 조작 한 번마다 확인한다.

```js
document.querySelectorAll('[role=dialog],[role=alertdialog]').length  // 0 이어야 한다
```

0이 아니면 먼저 닫고 다음으로 간다. **이미 떠 있는 얼럿은 새 노드가 아니라 옵저버에 안 잡힌다** —
옵저버 로그가 비어 있는 것은 「안내가 없다」의 근거가 못 된다. 버튼 조회가 빈 값이면 그 자체가 신호다.

**(다) 순차 검증 화면은 앞 필드에서 멈춘다.** 「B 검증이 없다」고 적기 전에 A 를 채웠는지 확인한다.

**(라) `readonly` input 의 값은 `innerText` 로 안 읽힌다.** 「값이 안 보인다」 전에 `value` 를 확인한다.

**(마)** 빈 상태 문구·플레이스홀더가 `[role=status]` 로 잡혀 토스트로 오인될 수 있다 — 문구를 눈으로 본다.

## 검사 축 4개

### ① UX 불편

명세에 없어도 사람이 불편하면 적는다. 구체적으로 셀 수 있게 적는다.

- 목표 달성까지 **클릭 수** — 자주 하는 일에 4클릭 이상이면 후보
- 되돌아가기 — 뒤로가기·ESC·모달 닫기가 작업을 날리는가. 필터가 초기화되는가
- 포커스 — 모달 열림 시 첫 입력에 커서가 가는가. Enter 로 검색·저장이 되는가
- 로딩 — 응답 대기 중 화면이 멈춘 것처럼 보이는가. 버튼 연타가 막히는가
- 스크롤 — 목록 조작 후 스크롤 위치가 튀는가. 표가 화면을 넘치는가
- 막다른 길 — 결과 0건 화면에서 다음 행동이 제시되는가

### ② 권한과 무관한 UI 의 데이터 일관성 — 계정 교차 비교

**이 축이 계정을 여러 개 쓰는 이유다.** 같은 화면을 계정마다 열어 표로 나란히 적는다.

| 관측점 | 최고권한 | 일부권한 | 일반 |
|---|---|---|---|
| 총 건수 | | | |
| 목록 첫 행 | | | |
| 합계·통계 값 | | | |
| 기본 날짜 범위 | | | |
| 정렬 순서 | | | |

**권한과 무관해야 할 값이 계정마다 다르면 후보다.** 반대로 권한 때문에 다른 것은 정상이니
「권한과 무관한 값인가」를 먼저 판단한다 — 조직 전체 통계는 권한 무관, 내 결재 대기 건수는 권한 종속.

권한 종속 UI 도 **표현 방식**은 본다 — 권한 없는 버튼이 계정에 따라 어떤 데는 숨고 어떤 데는
비활성이고 어떤 데는 눌리는데 실패하면, 그 **불일치**가 후보다.

### ③ 문구 통일성

- 같은 개념에 다른 용어 — 한 화면은 「정책 그룹」, 다른 화면은 「규칙 그룹」
- 존댓말·마침표 유무 혼용 — 「저장되었습니다.」 vs 「저장 완료」
- 버튼 라벨 — 같은 동작에 「등록」/「저장」/「추가」가 섞이는가
- 띄어쓰기 — 「임시저장」 vs 「임시 저장」
- 로케일 — 다국어 화면에 원본 언어가 남았는가, 반대로 영문 에러 화면이 뜨는가
- **문구는 그대로 인용해 적는다.** 요약하면 2차에서 명세와 글자 대조가 안 된다.

### ④ 기능 완성도

- 빈 상태 — 0건일 때 안내가 있는가, 문구가 두 번 렌더되지 않는가
- 실패 안내 — 조회·저장 실패 시 사용자가 아는가 (**실패를 삼키는 화면**이 가장 흔한 결함)
- 검증 누락 — 필수값 없이 저장되는가, 시작>종료가 저장되는가, 이미 처리된 건을 또 처리할 수 있는가
- 새로고침 — 저장한 값이 리로드 후 유지되는가
- 페이징 — 총 건수와 페이지 수가 맞는가. 마지막 건에 접근되는가
- 좁은 화면 — 표·칩이 잘리는가

## 기록 포맷

스크래치패드에 `pass1-raw-<날짜>.md`. **원인·파일경로 칸이 없다.** 상세 포맷은 `REPORT.md`.

핵심은 `사용자 영향` 칸을 반드시 채우는 것 — 2차에서 「기획의도」로 판정돼도 이 칸이 있으면
UX 개선 제안으로 남는다.

## 종료 — 자기점검을 출력한다

1차를 닫기 전에 **읽은 파일 목록**을 출력한다.

```
1차에서 읽은 파일:
  - <설정 파일>
  - <scratchpad>/pass1-raw-<날짜>.md
```

레포 경로·명세 문서가 하나라도 있으면 그 목록을 **표시하고, 영향받은 항목을 무효로 표시한 뒤
해당 항목만 다시 측정한다.** 조용히 넘기지 않는다.

이어서 사용자에게 보고한다 — **이슈 트래커에 올리지 않는다.**

```
1차 완료 · 후보 N건 (축별 ①x ②x ③x ④x)
테스트 서버에 남긴 변경: <있으면 목록, 없으면 "없음">
2차로 갈까요? 빼거나 추가할 항목이 있으면 말씀해 주세요.
```

사용자가 「2차 가자」라고 하기 전에 `PASS2-verify.md` 를 읽지 않는다.
