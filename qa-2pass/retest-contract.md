# 재시험 계약(기준표) 틀

`RETEST.md` 3) · 4) 의 산출물. 게이트에서 사용자에게 이 표를 보여 주고, 확인받은 표만 실행기에 넘긴다.

```markdown
# 재시험 계약 — <티켓 ID> <티켓 제목> · <날짜>
- 자리: [A] 사전 / [B] 확인 보조 / [C] 재작업 재시험
- 기준 원천: 트래커 본문 · 댓글 (대체: <붙여 넣기 등, 없으면 「없음」>)
- 시험할 빌드: <프론트 커밋 · 배포 시각>   (2) 반영 확인 결과)
- 연결 PR: #N, #M   (못 찾았으면 「없음 — 회귀 확장 없음」)
- 대상 주소: <테스트 서버 또는 로컬>
- 데이터 조작: 없음 / <게이트에서 허락받은 것>

| ID | 출처 | 계정 | 화면 · 폭 · 언어 · 데이터 | 조작 | 기대(PASS 조건) | 반증(FAIL 조건) | 확인 방법 |
|---|---|---|---|---|---|---|---|
| C1 | 본문 「기대 결과」-1 | <등급> | <경로> · 1440×900 · ko · <데이터 조건> | <클릭 순서> | <측정 가능한 문장> | <무엇이 보이면 실패인가> | <측정기 0건 / 문구 일치 / 요청 본문 / 캡처 열람> |
| C2 | 댓글 「확인 부탁」 2 | | | | | | |
| X1 | 확장 — 다른 진입점 | | | | | | |
| X2 | 확장 — 공용 부품 사용처 | | | | | | |
| X3 | 확장 — 최악 데이터 | | | | | | |
```

## 칸 규칙

- **출처**: `본문 <절 이름>-<번호>` · `댓글 <작성 시각>` · `결정 <번호>` · `지난 실패 <날짜>` · `확장 — <종류>` · `추정 기준`.
- **기대**는 측정 가능한 말로 쓴다. 「자연스럽게」 같은 말이 원문이면 원문을 괄호로 남기고 측정 가능한 해석을 쓴 뒤 출처에 `추정 기준`.
- **반증**이 비면 그 기준은 아직 시험할 수 없다 — 「무엇이 보이면 실패인가」를 채울 때까지 게이트에서 묻는다.
- **확인 방법**이 「눈으로 본다」뿐이면 안 된다. 최소한 「요소 캡처를 열어 <무엇>을 확인」으로 쓴다.
- 처음부터 못 재는 것(없는 계정 조합 · 실기기 전용)은 확인 방법 칸에 `BLOCKED 예정 — <이유>` / `실기기 확인 목록`.
- 기준이 10개를 넘으면(C + X) 게이트에서 우선순위를 묻는다 — 재시험은 고친 것의 확인이지 전수 QA 가 아니다.
