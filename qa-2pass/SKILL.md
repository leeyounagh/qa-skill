# 2단 QA

**왜 2단으로 나누는가.** 명세를 먼저 읽으면 명세가 서술한 것만 보게 된다 — 「명세대로 동작하지만
쓰기 불편한 것」은 영원히 안 잡힌다. 반대로 명세를 안 보고 끝내면 기획의도를 결함으로 올려
티켓 보드를 오염시킨다.

그래서 **1차는 아무것도 모른 채 사용자 눈으로 보고, 2차는 그 목록을 명세·코드로 검증한다.**
두 패스는 산출물 파일로만 연결된다. **1차 도중 명세·레포·이슈 트래커를 열지 않는 것이 1차의 유효성 전부다.**

## 0. 설정 로드 (항상 먼저)

환경별 값(테스트 서버 URL·계정·명세 위치·레포 경로)은 **스킬에 없다.** 설정 파일에서 읽는다.
설정은 **공통 파일 1개 + 도메인 파일 N개**로 나뉜다 — 계정 권한·기능 매핑·이슈 트래커 팀은 도메인마다 다르기 때문이다.

```bash
ls "$HOME"/.claude/projects/*/memory/reference_qa_environment.md 2>/dev/null \
  || ls "$HOME"/.claude/qa-2pass-config.md 2>/dev/null          # 공통
ls "$HOME"/.claude/projects/*/memory/reference_qa_env_*.md 2>/dev/null  # 도메인별
```

1. **공통 파일**을 읽는다(서버 호스트·레포·기준 브랜치·도메인 목록). 여러 개면 현재 작업 디렉터리에 대응하는 것.
2. **도메인을 정한다** — 인자 → 기능명이 속한 도메인 파일 매핑표 → 현재 작업 중인 앱 디렉터리 순. 그래도 모호하면 묻는다.
3. **그 도메인 파일**을 읽는다. 이후 「설정 파일」은 공통 + 도메인 두 파일을 합친 것을 뜻한다 (도메인 값이 우선).
   **다른 도메인 파일은 읽지 않는다** — 계정·매핑이 섞이면 권한 판정이 무너진다.

- 도메인 파일이 없으면 → `SETUP.md` 의 **도메인 온보딩**을 돌린다. QA 는 온보딩이 끝난 뒤 시작한다.
- 필수 필드가 `(미등록)` 이면 → `SETUP.md` 를 읽고 **그 항목만** 묻는다.
- 구버전(단일 파일에 계정·매핑까지 있는 형태)이면 그대로 쓰되, 끝에 도메인 분리를 제안한다.

## 1. 인자 파싱

```
/qa-2pass [도메인] [기능] [모드] [입력원]
```

| 인자 | 값 | 없을 때 |
|---|---|---|
| 도메인 | 공통 파일 도메인 목록의 키 (`hr`, `commerce` 등) — 생략 가능 | 0단계 2번 규칙으로 추론, 모호하면 묻는다 |
| 기능 | 도메인 파일 매핑표의 기능명. 탭 한정 가능 (`근태 외근관리`) | **묻는다** — 매핑표에서 선택지 생성 |
| 모드 | `1차` · `2차` · `3차` · `명세대조` · `재시험` | **묻는다** |
| 입력원 | 2차 모드에서 검증할 항목 목록의 출처 · 재시험 모드의 티켓 ID / 「확인 대기 전부」 / `사전 #PR` | 2차 · 재시험인데 없으면 **묻는다. 진행 금지** |

자연어도 같게 해석한다 — 「1차 건너뛰고 명세 대조부터」 = 모드 `명세대조`,
「이 목록 2차만 돌려줘」 = 모드 `2차` + 입력원은 붙여준 목록.

**기능을 임의로 정하지 않는다.** 「앱 전체」는 유효한 범위가 아니다 — 범위가 없으면
스윕이 무한하고, 무한하면 과보고가 된다. 과보고된 티켓은 결국 사람이 지운다.

## 2. 모드별 진입 조건

| 모드 | 2차가 소비할 입력 | 주의 |
|---|---|---|
| `1차` | 1차가 만든 `pass1-raw-<날짜>.md` | 기본 경로 |
| `2차` | **필수** — 파일 / 붙여넣은 목록 / 티켓번호 / QA 반려 목록 | 아래 경고 |
| `3차` | 명세 **부록(API·DTO·검증 규칙)** 이 항목 목록이 된다 | **선택 패스.** 부록이 없는 기능은 못 돈다 — 알리고 건너뛴다 |
| `명세대조` | 명세 조항 자체가 항목 목록이 된다 | 블라인드가 아니므로 1차 하드룰 미적용 |
| `재시험` | 티켓 원문(기대 결과 · 재현 · 확인 범위 · 확인 요청 댓글)이 기준표가 된다 | 블라인드 아님. **도메인 설정 「재시험」 절(SETUP C)이 비면 온보딩부터** · 상태 이동은 설정 C3 대로(사용자 확인 뒤) |

**2차만 돌릴 때 (입력이 남이 준 목록인 경우) 반드시 경고한다:**
> 실측 근거가 없어 오탐 필터가 약해집니다. 이 항목들을 직접 재현해 실측을 붙이고 판정할까요?

## 3. 착수 확인 (건너뛰지 않는다)

계정 여러 개 로그인 + 전 탭 스윕은 오래 걸린다. 범위가 틀리면 그게 전부 낭비다.
한 화면으로 보여주고 확인받는다.

```
도메인  <도메인> (<도메인 파일명>)
기능    <기능> · <탭>
계정    <설정 파일의 계정 등급 목록>
모드    1차부터
명세    <설정 파일의 명세 문서> (2차에서 읽음)
산출    <scratchpad>/pass1-raw-<날짜>.md
```

## 5. 반드시 묻는 지점 — 자동 승인 모드에서도

`AskUserQuestion` 은 자동 승인 모드에서도 사용자에게 그대로 올라간다. 억제되지 않는다.
위험은 도구가 막히는 게 아니라 **묻지 않고 스스로 판단해버리는 것**이다. 아래는 예외 없이 묻는다.

1. 기능·모드가 인자에 없을 때
2. 2차 모드인데 입력원이 없을 때
3. **1차 → 2차 진입 전** (1차 목록 검토 게이트)
4. 판정이 **「기획확인」** 으로 떨어질 때 — 오탐으로 밀지 않는다
5. **테스트 서버에 데이터를 남기는 조작 직전** — 삭제 경로가 없는 것은 특히
6. **이슈 등록 직전** — 부모 이슈·담당자·우선순위
7. 설정 매핑표에 없는 기능을 지정했을 때 (명세 위치를 묻고 행을 추가한다)
8. **2차 종료 후 3차를 돌릴지** — 기본은 돌리지 않는다. 명세에 API 부록이 있을 때만 제안한다
9. **재시험 기준표 확인 게이트** — 계약(C + 회귀 확장 X) · 계정 · 데이터 조작 여부
10. **재시험 결과를 트래커에 쓰기 직전** — 댓글 초안을 보여 주고 승인받는다
11. **재시험 온보딩**(SETUP C) — 비어 있는 ● 칸을 시작 전에 한 번에

## 6. 절대 하지 않는 것

- **1차 결과를 바로 이슈로 올리지 않는다.** 사용자 검토가 게이트다.
- **1차를 한 창 크기로 끝내지 않는다.** 축 ⑤ 표시 매트릭스의 필수 칸(최소 지원 폭 + 사이드바 펼침 · 모바일 최소 폭 · 긴 언어 · 최악 데이터)을 돌지 않은 1차는 화면 깨짐을 못 잡는다(`PASS1-blind.md` ⑤).
- **목업을 모든 항목에 그리지 않는다.** 화면을 봐야 이해되는 항목(모양 · 배치 · 화면 간 불일치 · 디자인 선택 · 스크린샷 불가)에만, 판정서는 페이지별로 묶는다(`MOCKUP.md`).
- **표시 깨짐을 「기획확인」 · 「UX 제안」으로 미루지 않는다.** 읽을 수 없거나 누를 수 없으면 결함이고, 기획에는 고칠 모양만 묻는다(`PASS2-verify.md` 5)).
- **2차 없이 티켓을 만들지 않는다.** 오탐 필터를 통과하지 않은 항목은 후보일 뿐이다.
- **2차 · 3차 결과를 「결함 N건」 한 덩어리로 내지 않는다.** 명세와 비교해 **A 명확한 결함**(조항 문언 위반 확정)과 **B 명확하지 않은 것**(대조군 근거 · 해석 필요 · 명세 침묵 · UX 제안 · 명세 정정 후보)으로 나눠 판정서 맨 위와 채팅 보고 모두에 낸다(`PASS2-verify.md` 6) · `REPORT.md`).
- **테스트 서버를 어질러 놓고 끝내지 않는다.** 변경한 것은 원복하고, 못 한 것은 보고에 남긴다.
- **재시험에서 상태는 설정 C3 대로만 옮긴다.** C3 이 개발자(재시험 쓰는 사람)에게 판정 · 이동을 맡긴 도메인이면 사용자 확인 뒤 옮기고, 다른 사람 몫이면 근거만 낸다(상태 지시도 쓰지 않는다). C3 을 추측하지 않는다.
- **재시험 절차에 도메인 값을 넣지 않는다.** 트래커 · 상태 이름 · 멘션 · 배포 확인법은 설정 C 절에서 읽는다 — 다른 도메인은 다른 트래커를 쓴다.
- 코드 근거를 워킹트리에서 읽지 않는다 — 배포 기준 브랜치에서 읽는다(`PASS2-verify.md`).
- **3차에서 토큰 신원을 확인하지 않고 프로브를 돌리지 않는다.** 재로그인이 조용히 실패해 이전 계정 토큰이 남는다 — JWT payload 를 디코드해 `username` 을 눈으로 본다(`PASS3-contract.md`).
